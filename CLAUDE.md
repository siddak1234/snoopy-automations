# snoopy-automations — read before doing anything

**Autom8x automations:** the logic the platform dispatches a run to, which calls back through the platform for everything it is not trusted to hold ([README.md](README.md)).
**PUBLIC**, by owner decision: an automation holds no secret by construction (platform invariant 3), so there is nothing here to hide and nothing that may ever be hidden.
Required check: `all-green`. The engineering standard this file follows: `snoopy-backend/docs/platform/ENGINEERING-STANDARD.md`.

## Start here

1. `/add-dir ../snoopy-backend` — **read only.** It holds the governance documents for every repository; editing it from here breaks rule 1.
2. Grep `snoopy-backend/docs/platform/AUTOM8X-MASTER-PLAN.md` for **§0 STATUS**: it names the open round and repository. **If it does not name `snoopy-automations`, you are in the wrong repo.** Say so and stop.
3. Then MASTER-PLAN §4 (rules of engagement) and §5's rows for this repository; SYSTEM-MANIFEST §6, §10a and §12.2; BUILD-PLAN Phase 25 and the ADRs it rests on (0021, the platform is the only sender; 0034, the step runner).
4. Verify state with commands (`git log`, `npm run verify`, `gh api`), never with recall: a document says what was true when it was written.

## Rules

1. **One repository per session.** A change `snoopy-backend`, `snoopy` or `snoopy-mobile` needs is a **finding**: paste-ready text for that repository's next session. Never edit across repositories.
2. **No secret of any kind, ever** — not a token, key, database URL or "local only" fixture secret. This repository is public and git history is permanent; secret-scanning push protection is the second line, not the first.
3. **Nothing imports or depends on `@snoopy/*`, and no automation depends on another.** The boundary is the wire format in `contract/schemas`. An automation builds with the SDK and the libraries under `packages/`, each packed into its own image, and may run any engine behind the serving shell (platform ADR-0034 decision 6). `test/architecture.test.ts` and `test/isolation.test.ts` enforce it.
4. **The SDK is the only outbound path.** `packages/automation-sdk` presents the run token and nothing else on every callback; mail goes through the platform's `mail` callback, never a customer's mailbox (platform ADR-0021).
5. **A flow is one pull request here, and the merge is the deploy.** A manifest is authored and validated in `manifests/`; when its pull request merges, CI's Deploy job starts the platform's Flow CD, which checks the commit, the attestation and the manifest itself and starts the version (platform ADR-0047; still no registration route). A flow needs no backend pull request and no client change: the website and the app draw it from its manifest and its blocks (platform ADR-0048) once the clients' block renderers ship (29.1.3), and image, chart and group since the platform's switch (29.1.15) and the SDK's copy (29.1.16); until then a flow that sends blocks waits ([order.md](.claude/skills/create-flow/templates/order.md)'s hold). Only a new vendor (one provider file in `snoopy-backend/providers/`) or a new block, page part, question form or target (a platform change, its ADR-0048 decision 12) needs the platform first. Steps: [README.md](README.md#adding-an-automation).
6. **`npm run verify` green before every commit** (Gates, below). Run `/code-review` on the diff, and `/security-review` on anything touching the run token, the callbacks or mail construction.
7. **Every change goes PR → CI → squash-merge.** `main` is protected by the `protect-main` ruleset; CI's jobs run on GITHUB_TOKEN; its one secret, Deploy's, and what it can reach are written once, in [ci.yml](.github/workflows/ci.yml)'s header.
8. **Standing constraints:** source files 400 lines or fewer (`test/architecture.test.ts`); no speculative abstractions; zero runtime dependencies unless a concrete automation demands one, and then audited; the automation rules in [automations/CLAUDE.md](automations/CLAUDE.md).
9. **No new documents.** The documents of record are `CLAUDE.md`, `README.md`, the directory READMEs and `docs/records/*`. Supporting files, not documents: `docs/MAP.md` (generated), `docs/docs-map.json`, folder CLAUDE.md files and `.claude/`. Decisions belong in the platform's ADRs and discrepancies in its manifest §12, both through a backend session, as findings.

## Invariants

- An automation receives a run-scoped token at runtime and nothing else. There is no environment file here and there must never be one ([.gitignore](.gitignore)).
- `contract/schemas` is vendored byte-for-byte from the platform and never reformatted ([contract/README.md](contract/README.md)).
- Each package under `packages/` ships its built `dist` on Node built-ins alone (`test/architecture.test.ts`).
- A summary never carries the document it describes.
- Each version's origin is `http://<templateId>-v<n>.autom8x.internal:8080`, with a service account of its own ([README.md](README.md#adding-an-automation)).

## Gates and push

- Work in a scratch clone under `/private/tmp`, never in `~/Desktop` or iCloud Drive. One heavy gate at a time on the machine: hold the gate lock.
- Commit, then run the gate on the committed tree:

```bash
npm ci --ignore-scripts                       # install exactly what CI audited
npm run verify                                # format:check → check:docs → map --check → reference audit → build → typecheck → test → repo facts
npm audit --omit=dev --audit-level=high       # CI's blocking audit, which verify skips
npm run facts                                 # after adding or removing files
npm run map                                   # after adding a file under a glob docs/docs-map.json lists
npm run format                                # fix formatting
```

- Push normally, never with `--no-verify`. A PR is ready only when it is pushed, `all-green` is green on its head, and its body is final.
- CI ([.github/workflows/ci.yml](.github/workflows/ci.yml)): List (every `automations/*/Dockerfile`), Verify, then Image and Publish once per automation it lists, then Deploy on a push to main, then `all-green`.
- `.claude/settings.json` runs the shared kit's hooks (canonical in `snoopy-backend`; the standard's section (h)): `guard.mjs` blocks `--no-verify` pushes, `rm -rf` outside the repository and the temp folders, builds under `~/Desktop` or iCloud Drive, writes into iCloud Drive and `hygiene --execute`; `session-start.mjs` prints git and hygiene facts; `stop-check.mjs` warns about processes left running.

## Docs always updated

Every change updates every doc and code comment that describes it, in the same commit, one place each; the others link. [docs/docs-map.json](docs/docs-map.json) maps code to its docs, and `npm run check:docs` (`scripts/kit/check-docs.mjs`, the standard's section (e)) fails when mapped code changes without its doc, a reference stops resolving, or a fact is typed in a second place. A commit that changes no doc on purpose says why in a `Docs-Unchanged: <reason>` trailer. The `reviewer` agent reads what a script cannot.
