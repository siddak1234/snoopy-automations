## Pass 1 (p1): the first pass: practice, rules, vendors and the process

### How the work runs today, end to end

- The coder codes only conditions that exist and affect care at this visit, and works to the highest certainty the note gives. Uncertain diagnoses are not coded as confirmed. [p1-practice-3, p1-practice-1]
- The code set in force for a visit dated 2026-10-28 is FY2027 (visits from 2026-10-01 to 2027-09-30), and following the guidelines is required by HIPAA. [p1-rules-1, p1-rules-3]

### Where the time and the errors go

- Most Medicare fee-for-service improper payments (CMS CERT 2021, as reported by AAPC) come from documentation that does not support the claim (64.1%), with incorrect coding at 10.6%. Overall rate was 6.26% ($25.03 billion). These are all claim types, not diagnosis codes or nephrology. [p1-streamlining-10]

### What an expert checks

- 2. Is the supporting line from the patient's own provider, and does the note state the condition as certain (not probable, suspected, rule out, working diagnosis)? [p1-practice-12, p1-practice-1, p1-rules-9]
- 3. Does the condition exist and affect care at this visit, not just carried forward? [p1-practice-3]
- 6. AKI and CKD are both coded, neither standing in for the other. Order depends on the visit. [p1-practice-6]
- 7. CKD stage: N18.6 only when the doctor wrote ESRD, and then no N18.x stage code beside it. Transplant patient with CKD gets N18 stage plus Z94.0. [p1-practice-7, p1-practice-8]
- 9. Linked conditions under the index 'with' convention are coded as related unless the note says unrelated. [p1-practice-9, p1-rules-7]

### The rubric

- Each code gets one verdict: supported (keep, no action), change suggested (with the supporting note line), or needs a query (to the doctor). [p1-streamlining-2, p1-practice-2, p1-practice-11]
- A more specific code is suggested only when a note line supports it. Otherwise keep the code or ask for documentation. [p1-practice-2, p1-rules-10]
- Uncertain wording on a condition: suggest the symptom, sign or abnormal result in its place, or ask for documentation. [p1-practice-1, p1-rules-9]

### The rules that bind a result

- The model never invents a code. Candidate codes come from the official table, and the model only ranks or matches them to the note. [p1-streamlining-11, p1-streamlining-2, p1-rules-2]
- Do not override the doctor's stated diagnosis on clinical grounds alone. Send conflicts to a query. [p1-practice-11, p1-rules-8]
- Show results with blocks (table, list, badge), not documents[], which is built for bills and receipts. [p1-streamlining-6, p1-streamlining-1]
- Bad inputs (blank file, unreadable scan, no codes, several patients in one file) fail with a plain reason of 200 characters or less. Inputs a person should review hold instead. [p1-streamlining-8, p1-streamlining-3]

### The simplest first version

- Step 1, screening: reject files that are not clinical notes or not from a specialty the clinic turned on. This use of screening is an inference. [p1-streamlining-2]
- Step 2, extraction: pull the codes on the chart and the note facts. [p1-streamlining-2]
- Step 4, classification: sort each code as supported, unsupported or needs a query. Summarization drafts each change with its note line. [p1-streamlining-2, p1-practice-2]
- Setup: the clinic picks specialties with separate toggles (nephrology, internal medicine, cardiology), because setup has no dropdown. Nephrology checks are the deepest. [p1-streamlining-4, p1-practice-4, p1-practice-7]

### When it goes wrong

- The model suggests a code that is more specific than the note supports. Guard: require a note line, otherwise keep. [p1-practice-2]
- The note is quoted with markup-like text and the result fails the display schema. Guard: clean the quote first. [p1-streamlining-9]
- Unreadable, blank or empty file, no codes found, or several patients in one file: the run fails with a plain reason. [p1-streamlining-8]
- Visit date outside FY2027 uses the wrong code set. [p1-rules-1]
- Note written by a nurse or dietitian is used as the supporting line for a diagnosis. [p1-practice-12]

### Golden cases (invented data)

- Chart codes: N18.4 and N18.6. Note says 'ESRD, previously stage 4.' → Remove N18.4 and keep N18.6 only. Held for approval. [p1-practice-7]
- Chart code: I50.9 for 'suspected heart failure, rule out' in a clinic visit. → Unsupported as confirmed. Suggest the symptom or abnormal result in the note, or ask for documentation. Held for approval. [p1-practice-1, p1-rules-9]
- Chart code N18.3x only. Note says 'CKD stage 3, with acute kidney injury today.' → Add the AKI code. Do not let the N18 code stand in for it. Held for approval. [p1-practice-6]
- A blank file uploaded from https://example.com/notes/blank.pdf → Run fails with a plain reason: no readable note or codes. [p1-streamlining-8]
